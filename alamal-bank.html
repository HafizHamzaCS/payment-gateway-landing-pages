The problem

Al Amal Bank customers want to pay online. Give them a checkout that lets them.

Al Amal Bank doesn't provide a WooCommerce plugin — so stores fall back to manual bank transfers and spreadsheet reconciliation. This gateway adds SMS-confirmed Al Amal payments directly to your checkout, with proper security and order handling.

Features

Secure bank payments, simplified.

✉

SMS confirmation at checkout

Customers confirm payment with an SMS code — embedded in block and classic checkouts, no redirects.

🔒

HTTPS enforced in live mode

The plugin refuses to talk to the bank over anything but verified HTTPS in production. No exceptions.

⬢

Rate-limited SMS flow

Code requests are throttled per IP and expire after 15 minutes — SMS spam and replay abuse blocked.

⛨

Verification bound to the order

Each SMS code is tied to the account and cart total, and re-validated at payment — codes can't be reused or swapped.

Security

Paranoid about bank traffic.

HTTPS-only in production

Live mode refuses non-HTTPS bank endpoints outright, and TLS certificate verification stays on — bank credentials never travel in the clear.

Nonce-verified payments

Every payment request carries a verified nonce — classic and block checkouts both — blocking forged payment submissions.

Expiring, single-use codes

SMS codes expire after 15 minutes and are bound to one account and one cart total. A changed cart invalidates the code.

Minimal data footprint

Only the bank's response code and message are stored on the order — full API payloads and credentials never touch your database or logs.
